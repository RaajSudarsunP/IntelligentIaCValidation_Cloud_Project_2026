# Deployment & AWS Cloud Implementation Guide

This guide walks you through running the **Intelligent IaC Assurance Framework** locally with Docker and deploying it to **Amazon Web Services (AWS)** using production-grade Infrastructure as Code (Terraform).

---

## 1. System Architecture on AWS

| Component | AWS Service | Purpose |
| :--- | :--- | :--- |
| **Edge & Presentation** | Amazon CloudFront (CDN) + S3 | Global HTTPS delivery of React Vite SPA |
| **API Load Balancer** | Application Load Balancer (ALB) | Routes external traffic to ECS Fargate backend |
| **Backend Service** | AWS ECS Fargate (`backend`) | FastAPI service handling validation & reporting |
| **ML Engine** | AWS ECS Fargate (`ml-engine`) | Modules 1–9 multi-agent validation & Checkov |
| **AI Reasoning** | Amazon Bedrock (Claude 3.5 Sonnet / Titan) | LLM inference for explainable remediation advice |
| **Telemetry & Drift** | Amazon CloudWatch & AWS Config | Real-time infrastructure drift monitoring |
| **Storage Layer** | Amazon S3 | Secure bucket for IaC files & report storage |
| **Database** | Amazon DocumentDB (MongoDB-compatible) | Managed NoSQL storage for histories & metrics |

---

## 2. Option A: Test Locally with Docker Compose

Before pushing to the cloud, you can run the entire 4-tier stack on your local machine:

```bash
docker compose up --build
```

- **Frontend Application**: `http://localhost:3000`
- **FastAPI Backend**: `http://localhost:8000` (Docs: `http://localhost:8000/docs`)
- **ML Validation Engine**: `http://localhost:9000` (Health: `http://localhost:9000/health`)
- **MongoDB**: `localhost:27017`

To shut down:
```bash
docker compose down -v
```

## 3. Option B: Deploying to AWS

### Prerequisites

1. **AWS Account**: An active AWS account with administrative permissions.
2. **AWS CLI**: Installed and configured. Run:
   ```bash
   aws configure
   ```
   *(Enter your `AWS Access Key ID`, `AWS Secret Access Key`, and preferred region like `us-east-1`)*.
3. **Terraform**: [Terraform CLI (>= 1.5.0)](https://developer.hashicorp.com/terraform/install) installed.
4. **Docker**: Docker Desktop running on your machine.
5. **Bedrock Model Access**:
   - In AWS Console, navigate to **Amazon Bedrock** -> **Model access**.
   - Click **Manage model access** and enable **Anthropic: Claude 3.5 Sonnet** (or **Amazon: Titan Text**).

---

### Step-by-Step Deployment

#### Method 1: Using Automated Script (Recommended)

**On Windows (PowerShell):**
```powershell
.\deploy\deploy.ps1 -Region "us-east-1"
```

**On Linux / macOS (Bash):**
```bash
chmod +x ./deploy/deploy.sh
./deploy/deploy.sh us-east-1
```

The script will automatically:
1. Initialize and apply the Terraform infrastructure.
2. Authenticate Docker with Amazon ECR.
3. Build and push container images for Backend and ML Engine.
4. Build the React frontend bundle and sync it to the S3 bucket.
5. Trigger ECS service redeployment.
6. Print your public CloudFront website URL.

---

#### Method 2: Manual Step-by-Step with Terraform

1. **Provision Infrastructure**:
   ```bash
   cd deploy/terraform
   cp terraform.tfvars.example terraform.tfvars
   # (Optional: edit terraform.tfvars to change region or passwords)
   terraform init
   terraform apply
   ```

2. **Note the Outputs**:
   Terraform will display:
   - `cloudfront_domain_name` (e.g. `d111111abcdef8.cloudfront.net`)
   - `alb_dns_name`
   - `s3_frontend_bucket`
   - `ecr_backend_url`
   - `ecr_ml_engine_url`

3. **Build & Push Docker Containers**:
   ```bash
   cd ../..
   # Log in to ECR
   aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin <YOUR_ACCOUNT_ID>.dkr.ecr.us-east-1.amazonaws.com

   # Backend
   docker build -t <ecr_backend_url>:latest -f Dockerfile.backend .
   docker push <ecr_backend_url>:latest

   # ML Engine
   docker build -t <ecr_ml_engine_url>:latest -f Dockerfile.ml .
   docker push <ecr_ml_engine_url>:latest
   ```

4. **Deploy Frontend to S3**:
   ```bash
   cd Frontend
   npm install
   npm run build
   aws s3 sync dist s3://<s3_frontend_bucket> --delete
   ```

## 4. Verifying Your Live Deployment

1. Open your browser and navigate to the **CloudFront URL** (`https://<cloudfront_domain_name>`).
2. Go to the **Validate** page.
3. Upload any sample Terraform file (e.g. `src/ml_model/module1_iac_parser/sample_terraform.tf`).
4. Click **Run Assurance Pipeline**:
   - The file is saved directly into your **Amazon S3** storage bucket.
   - The **ECS Fargate backend** forwards the template to the **ECS ML engine**.
   - Findings, consensus, and remediation proposals are calculated and stored in **Amazon DocumentDB**.
   - If `USE_AWS_BEDROCK=true`, real AI recommendations are generated by Claude 3.5 Sonnet on AWS Bedrock.
5. View the dashboard to inspect security scores, drift metrics, and blast radius graphs.

## 5. Clean Up / Teardown (Prevent Unwanted AWS Charges)

When you are finished testing and want to destroy all created AWS resources:

```bash
# Empty S3 buckets first so Terraform can delete them cleanly
aws s3 rm s3://<s3_frontend_bucket> --recursive
aws s3 rm s3://<s3_storage_bucket> --recursive

# Run Terraform destroy
cd deploy/terraform
terraform destroy -auto-approve
```
